# 工作流程与验收清单

出品与维护：AIGC-DAO

本文档说明完整的设计实现流程和验收标准。阅读前提：已阅读 [SKILL.md](../SKILL.md) 入口文件。

---

## 1. 实现步骤

### 步骤 1：调研

**了解技术栈**
```
□ 框架：React / Vue / Svelte / 原生 / 其他
□ 构建工具：Vite / Webpack / 其他
□ CSS 方案：原生 CSS / CSS Modules / Tailwind / Styled Components / 其他
□ 现有设计系统或组件库
□ 代码规范和文件结构
```

**了解界面类型**
```
□ 营销页/落地页 → 视觉冲击、留白、大字体
□ 工作型应用 → 信息密度、快速扫描
□ 数据密集界面 → 紧凑但可读、对齐
□ 内容阅读 → 阅读舒适、行高
```

### 步骤 2：设计意图

写 2-3 句概括：
- 目标受众是谁
- 主要操作路径
- 视觉风格方向

**示例**：
> 这是面向开发者的 API 文档站点。用户需要快速查找和复制代码示例。采用清爽的浅色主题，强调代码可读性和导航效率。

### 步骤 3：结构先行

先写语义化 HTML，不考虑样式：

```html
<main>
  <header>
    <h1>页面标题</h1>
    <p>页面描述</p>
  </header>
  
  <section aria-labelledby="section-title">
    <h2 id="section-title">区块标题</h2>
    <!-- 内容 -->
  </section>
</main>
```

### 步骤 4：样式实现

从 tokens 开始，复用变量：

```css
/* 1. 引入或定义 tokens */
@import 'tokens.css';

/* 2. 布局 */
.page { ... }

/* 3. 组件 */
.card { ... }

/* 4. 状态 */
.card:hover { ... }
```

### 步骤 5：状态补全

检查每个交互组件：

```
□ default 默认
□ hover 悬浮
□ focus-visible 键盘焦点
□ active 按下
□ disabled 禁用
□ loading 加载中
□ error 错误
□ success 成功
□ empty 空状态
```

### 步骤 6：响应式与暗色

```
□ 移动端布局（< 768px）
□ 平板布局（768-1024px）
□ 桌面布局（> 1024px）
□ 暗色模式配色
□ prefers-reduced-motion
```

### 步骤 7：无障碍检查

```
□ 语义化 HTML
□ 标题层级正确
□ 表单有标签
□ 图片有替代文本
□ 焦点可见
□ 对比度达标
```

### 步骤 8：视觉审查

对照原则逐项检查：
```
□ 单一焦点
□ 三级层次
□ 间距一致
□ 对齐正确
□ 色彩克制
□ 圆角统一
```

## 2. 验收清单

### 2.1 功能验收

```
□ 所有链接可点击
□ 所有按钮有响应
□ 表单可提交
□ 动态内容正确加载
□ 错误状态有处理
```

### 2.2 视觉验收

**断点截图**
```
□ 移动端（375px 宽）
□ 平板（768px 宽）
□ 桌面（1280px 宽）
□ 超宽屏（1920px 宽）- 可选
```

**视觉一致性**
```
□ 间距符合系统
□ 字体大小符合层级
□ 颜色使用正确
□ 圆角统一
□ 阴影层级正确
```

### 2.3 无障碍验收

```
□ 键盘 Tab 遍历所有交互元素
□ 焦点环可见
□ 文字对比度 ≥ 4.5:1（可用 DevTools 检查）
□ 标题层级无跳级
□ 表单字段有关联标签
```

### 2.4 动效验收

```
□ prefers-reduced-motion: reduce 时动画禁用或简化
□ 动效有目的（反馈/引导/状态）
□ 时长合理（≤ 400ms）
```

### 2.5 技术验收

```
□ 浏览器控制台无错误
□ 项目现有测试通过
□ 无 lint 错误
□ CSS 无冗余/未使用样式
```

## 3. 诚实说明

验收报告应诚实说明：

**已测试**：
- 列出实际测试的浏览器和设备
- 列出执行的检查项

**未测试**（示例）：
- 未进行真机测试
- 未进行屏幕阅读器测试
- 未进行性能分析（Lighthouse）
- 未测试 IE/旧版浏览器
- 未进行自动化 E2E 测试

## 4. 常见问题处理

### 4.1 现有样式冲突

```css
/* 使用更具体的选择器 */
.my-component .btn { ... }

/* 或使用 CSS Layers */
@layer base, components, overrides;

@layer components {
  .btn { ... }
}
```

### 4.2 设计系统不完整

```
1. 先补全必要的 tokens
2. 记录缺失项
3. 在验收报告中说明
```

### 4.3 时间有限

```
优先级排序：
1. 核心功能可用
2. 主要断点适配
3. 基础无障碍（焦点、对比度）
4. 暗色模式
5. 动效细节
```

## 5. 交付格式

### 5.1 代码交付

```
□ 按项目现有结构组织文件
□ 遵循项目命名惯例
□ 添加必要注释（非显而易见的逻辑）
□ 不添加无意义注释
```

### 5.2 文档交付

```
□ 组件用法说明（如需要）
□ 已知限制
□ 后续建议
```

### 5.3 验收报告

```markdown
## 已完成
- [x] 功能项 1
- [x] 功能项 2

## 已测试
- Chrome 120, macOS
- 键盘导航
- 对比度检查

## 未测试
- 移动端真机
- 屏幕阅读器
- Safari

## 已知问题
- 问题描述及临时解决方案

## 后续建议
- 建议项 1
- 建议项 2
```

## 6. 不承诺什么

- ❌ 不承诺完全符合 Apple Human Interface Guidelines
- ❌ 不承诺所有浏览器完美兼容
- ❌ 不承诺 Lighthouse 满分
- ❌ 不承诺无需后续迭代
- ❌ 不承诺适合所有项目场景

本 Skill 提供方法论和参考实现，实际效果取决于具体项目约束和执行情况。
